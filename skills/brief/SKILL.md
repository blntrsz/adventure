# Brief

## Steps

1. Read PRODUCT.md and TEAM.md. If the job to be done is missing, say so and still write a brief that points at the hole.
2. Use `templates/brief.md`. Problem is who hurts and how we know. Outcome is a production metric, not a screen list.
3. Scope: in, out, later. Constraints: legal, brand, partner, date.
4. Open questions each name a lane. Unowned questions stay in the brief; they are not silently assumed.
5. Write under `docs/briefs/`. Offer a packet to design or eng.

**Done when** the file exists, the outcome is checkable, and every open question has a lane.

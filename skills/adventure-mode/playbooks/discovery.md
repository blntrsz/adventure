**Lane: pm.** Problem and outcome before UI or tickets.

1. Read `PRODUCT.md`, `TEAM.md`, and any existing brief. Name the consumer and the pain in their words.
2. Draft or update a brief under `docs/briefs/` from `templates/brief.md`. Outcome is a production metric.
3. Run **grilling**. Frontier questions that are facts: look them up. Preference and policy: ask the PM lane.
4. Run **domain-modeling** for any term that will appear in tickets. Write `CONTEXT.md` rows.
5. Name other lanes this brief needs. Open a **packet** to design and/or eng with a checkable done when.
6. Stop. Do not spec or build. Tell the user the next slash command (`/critique`, `/spec`, or `/align` with eng present).

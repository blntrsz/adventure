# Prototype Quest Guide

Treat the prototype as an instrument for learning, not a partial production implementation.

1. State the hypothesis and the observation that would support or reject it.
2. Choose the smallest disposable experiment that produces that observation. Identify shortcuts that make it unsuitable for production.
3. Build and run the experiment. Capture concrete observations, including surprising failure modes.
4. Stop when the hypothesis is resolved; additional polish is outside this Quest.
5. Post the hypothesis, method, observations, conclusion, and downstream constraints to the Journal.
6. Remove temporary files unless the ticket requests a retained prototype. Report any retained code and its non-production limitations explicitly.

Mark the outcome ready for user review. A production implementation requires a separate accepted Task Quest.
